The [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) is the open standard through which AI agents discover and call tools. `Repl.Mcp` makes your entire command surface MCP-native with one line of code — then lets you fine-tune every aspect of how it's exposed.

## Enable MCP

```csharp
using Repl.Mcp;

app.UseMcpServer();      // exposes everything as MCP tools
return app.Run(args);
```

Start the server:

```bash
myapp mcp serve
```

Configure your agent (paths vary by client — see below):

```json
{
  "mcpServers": {
    "myapp": { "command": "myapp", "args": ["mcp", "serve"] }
  }
}
```

**Agent config file locations:**

| Agent | Path |
|---|---|
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` (Windows) / `~/.config/Claude/...` (macOS) |
| Claude Code | `.claude/settings.json` or `~/.claude.json` |
| VS Code Copilot | `.vscode/mcp.json` or `~/.mcp.json` |
| Cursor | `.cursor/mcp.json` or `~/.cursor/mcp.json` |
| MCP Inspector | UI-based |

## Command → MCP mapping

Every `Map(...)` call becomes an MCP tool automatically. The tool name is derived from the route (spaces replaced by `_`). The description comes from `[Description]` or `.WithDescription(...)`.

| Repl declaration | MCP surface | Notes |
|---|---|---|
| `app.Map(...)` | Tool | Default — always a tool |
| `.ReadOnly()` | Tool + auto-promoted Resource | URI derived from route |
| `.AsResource()` | Resource only | Not callable as tool; URI derived from route |
| `.AsPrompt()` | Prompt | Callable as MCP prompt |
| `.AsMcpAppResource()` | Tool + `ui://` HTML resource | Returns HTML for capable clients |
| `.AutomationHidden()` | Excluded | Human-only command |

### Tool naming

Default: `contact add` → `contact_add`. Customize the separator:

```csharp
app.UseMcpServer(o => o.ToolNamingSeparator = ToolNamingSeparator.Hyphen);
// contact add → contact-add
```

## Behavioral annotations

Annotations tell the agent **how** to call your tool — whether it should ask for confirmation, whether it's safe to parallelize, whether it can be retried:

```csharp
app.Map("contacts delete {id:int}", (int id, IContactStore store) =>
{
    store.Delete(id);
    return Results.Success("Contact deleted.");
})
.WithDescription("Permanently delete a contact.")
.Destructive();   // warn agent before calling; not safe to parallelize
```

| Annotation | Meaning for the agent |
|---|---|
| `.ReadOnly()` | No side effects — call freely, parallelize |
| `.Destructive()` | Side effects — warn user, don't parallelize |
| `.Idempotent()` | Safe to retry on transient failure |
| `.OpenWorld()` | Reaches external systems (email, HTTP, etc.) |
| `.LongRunning()` | Slow-operation hint in help and docs; not advertised to MCP clients as task support |
| `.AutomationHidden()` | Exclude from MCP; visible in interactive REPL only |

## Resources

Expose read-only data as MCP resources — the agent can subscribe, list, and read without invoking a tool:

```csharp
app.Map("contacts export", (IContactStore store) => store.All())
    .AsResource()
    .WithDescription("All contacts as a live JSON resource.");
```

The resource URI is derived from the route.

Use `.ReadOnly()` for the common case of "tool that's also readable as a resource":

```csharp
app.Map("contacts {id:int} show", (int id, IContactStore store) => store.Get(id))
    .ReadOnly()
    .WithDescription("Get contact by ID.");
// Registered as both tool 'contacts_show' and a resource with a URI derived from the route
```

## Prompts

Prompt templates let the agent inject pre-built context into an LLM conversation:

```csharp
app.Map("prompts summarize {id:int}", (int id, IContactStore store) =>
{
    var contact = store.Get(id);
    return new McpPromptResult
    {
        Messages =
        [
            new McpMessage(McpRole.User,
                $"Summarize the following contact and suggest follow-up actions:\n\n{contact}")
        ]
    };
})
.AsPrompt()
.WithDescription("Generate a summary prompt for a contact.");
```

Non-optional route arguments are advertised as `required` in `prompts/list`, matching the validation `prompts/get` applies. Handlers that return a plain `string` surface it as the prompt's text — not as a quoted JSON string literal.

## MCP Apps

MCP Apps are HTML surfaces rendered inside capable clients (e.g., Claude). The same `Map(...)` call serves launcher text for tool invocation and HTML for `resources/read`:

<Aside type="caution">
Always HTML-encode user-controlled values before embedding them in MCP App HTML. Raw interpolation creates stored XSS — an attacker who controls contact data can execute scripts in the MCP client's WebView.
</Aside>

```csharp
using System.Net;   // WebUtility.HtmlEncode

app.Map("contacts dashboard", (IContactStore store) =>
{
    var contacts = store.All().ToList();
    return $$"""
        <!DOCTYPE html>
        <html>
        <head><title>Contacts ({{contacts.Count}})</title></head>
        <body>
          <h1>Contacts</h1>
          <ul>{{string.Join("", contacts.Select(c =>
              $"<li><b>{WebUtility.HtmlEncode(c.Name)}</b> — {WebUtility.HtmlEncode(c.Email)}</li>"))}}</ul>
        </body>
        </html>
        """;
})
.AsMcpAppResource()
.WithDescription("Open the contacts dashboard.")
.WithMcpAppDisplayMode(McpAppDisplayMode.Inline);
```

Configure Content Security Policy for apps that load external assets:

```csharp
.WithMcpAppCsp(csp => csp.AddScriptSrc("https://cdn.myapp.io"))
```

## Paged tools

Any handler that injects <ApiRef uid="Repl.IReplPagingContext" /> or returns <ApiRef uid="Repl.ReplPage`1" label="ReplPage&lt;T&gt;" /> / <ApiRef uid="Repl.IReplPageSource`1" label="IReplPageSource&lt;T&gt;" /> is automatically a paged tool. Repl adds two reserved inputs to its MCP tool schema:

```json
"_replCursor":   { "type": "string",  "description": "Continuation cursor from a previous call" }
"_replPageSize": { "type": "integer", "description": "Number of items to return per page" }
```

Paged results are returned as structured content with an explicit page envelope:

```json
{
  "$type": "page",
  "items": [ { "id": 1, "name": "Alice" } ],
  "pageInfo": {
    "cursor": null,
    "nextCursor": "25",
    "totalCount": 500,
    "pageSize": 25,
    "hasMore": true
  }
}
```

To continue, the agent calls the tool again with `_replCursor` set to the previous `pageInfo.nextCursor`.

### Text fallback

Agents that read only `Content[0].Text` instead of `StructuredContent` need a text representation. Configure it via `ReplMcpServerOptions.PagedResultTextMode`:

```csharp
app.UseMcpServer(o =>
{
    o.PagedResultTextMode = McpPagedResultTextMode.SummaryOnly;
    // SerializedJson (default) | SummaryOnly | SummaryAndSerializedJson
});
```

`SerializedJson` maximizes compatibility. `SummaryOnly` ("42 items, page 1 of 20") saves tokens for structured-content-aware agents.

### Cursor validation

Repl validates `_replCursor` before use: empty strings, whitespace, control characters, values starting with `-`, and values longer than 512 characters are all rejected. Build cursor values that satisfy these constraints (base64 works well for structured data).

See [Result-Flow Paging](/reference/result-flow-paging/) for the full paging model and [Cursor Patterns](/reference/cursor-patterns/) for encoding strategies.

## Interaction in MCP mode

Repl routes <ApiRef uid="Repl.Interaction.IReplInteractionChannel" /> calls through MCP primitives when running as an MCP server. The mode decides what happens when the tool arguments do not answer a prompt:

```csharp
app.UseMcpServer(o =>
{
    o.InteractivityMode = InteractivityMode.PrefillThenFail;
    //  PrefillThenFail        — the prompt's default, else fail (default)
    //  PrefillThenDefaults    — the prompt's default, else the first choice, false or empty
    //  PrefillThenElicitation — legacy: elicitation, then sampling, then fail
    //  PrefillThenSampling    — legacy: sampling, then fail
});
```

**Design for agents:** prefer accepting all required data as route parameters or named options. Reserve <ApiRef uid="Repl.Interaction.IReplInteractionChannel" /> prompts for the human-interactive experience — agents should pass everything upfront.

For direct access to sampling and elicitation, which are legacy on `2026-07-28`, see [MCP — Advanced](/reference/mcp-advanced/).

## Rich tool descriptions

Tools can carry extended Markdown documentation for the agent, separate from the human-facing `--help` text:

```csharp
app.Map("contacts add {name} {email:email}", handler)
    .WithDescription("Add a new contact.")
    .WithDetails("""
        Creates a new contact record with the given name and email.

        **Rules:**
        - Email must be unique across all contacts.
        - Name cannot exceed 200 characters.
        - Returns the new contact's ID on success.

        **Example:**
        `contacts_add` with `name="Alice Dupont"`, `email="alice@example.com"`
        """);
```

`WithDetails(...)` content appears in the MCP tool schema but not in `--help` output.

## Controlling tool visibility

Hide individual commands from MCP:

```csharp
app.Map("debug reset", handler)
    .AutomationHidden();       // hidden from MCP, visible in interactive REPL
```

Filter at the server level:

```csharp
app.UseMcpServer(o =>
{
    o.CommandFilter = cmd => !cmd.Tags.Contains("internal");
});
```

Use module presence predicates for context-sensitive visibility:

```csharp
app.MapModule(
    new AdminModule(),
    (IAuthService auth) => auth.IsAdmin());
```

To scope visibility to workspace roots (native MCP roots or soft-root fallbacks, both legacy on `2026-07-28`), see [Client roots and soft roots](/reference/mcp-advanced/#client-roots-and-soft-roots).

A single option can be hidden too. A [hidden option](/reference/routes-and-parameters/#hidden-options) is left out of the tool schema, and a call that supplies it is rejected. `.WithOption(name, o => o.AutomationHidden())` hides an option from agents only.

On protocol revision `2026-07-28`, every client must see the same tool set, so a presence predicate that depends on the client's capabilities is evaluated against fixed answers. See [Protocol revisions](/reference/mcp-advanced/#protocol-revisions).

## Full configuration reference

```csharp
app.UseMcpServer(o =>
{
    o.ServerName               = "MyApp";
    o.ToolNamingSeparator      = ToolNamingSeparator.Underscore;
    o.InteractivityMode        = InteractivityMode.PrefillThenFail;   // the default
    o.ResourceFallbackToTools  = true;   // resources also callable as tools (compatibility fallback)
    o.PromptFallbackToTools    = true;   // AsPrompt() tools also callable as tools
    o.CommandFilter            = cmd => true;
    o.DynamicToolCompatibility = DynamicToolCompatibilityMode.Disabled;  // → see MCP — Advanced for shim mode
});
```

## Best practices

**Design for agents first.** Commands that work well for agents work well for humans too. The reverse is not always true.

**Use typed constraints.** Route constraints generate typed JSON Schema properties — `{id:int}` becomes `"type": "integer"` in the tool schema. An agent that knows the type can fill parameters correctly without guessing.

**One concern per tool.** A command named `contacts_sync_import_and_notify` is hard for an agent to reason about. Prefer `contacts_import` and `contacts_notify` as separate tools.

**Annotate everything destructive.** Missing `.Destructive()` on a delete command may cause an agent to call it without warning. When in doubt, annotate conservatively.

**Keep tool names short.** Agents have context windows. `contacts_list` is better than `contact_management_list_all_records`. Prefer short, noun-verb names.

**Test with MCP Inspector.** Run `myapp mcp serve` and point MCP Inspector at it to verify tool schemas, annotations, and resources before connecting a real agent.
