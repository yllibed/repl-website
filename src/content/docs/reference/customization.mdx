Repl's output pipeline is fully composable. The same command graph produces plain text for a CI log, syntax-highlighted JSON for a terminal, and Spectre.Console tables for a rich interactive session — all without touching handler code.

## Output formats

Every command supports output format flags out of the box:

| Flag | Format |
|---|---|
| *(none)* | `human` — plain text / table |
| `--output:format=json` (or `--json`) | JSON |
| `--output:format=xml` | XML |
| `--output:format=yaml` | YAML |
| `--output:format=markdown` | Markdown table |
| `--output:format=spectre` | Spectre.Console rendering |

### Format selection order

1. `--output:format` flag on the command line
2. `ReplOptions.Output.DefaultFormat` (configured at startup)
3. `human` (built-in default)

### Set the default format

```csharp
app.Options(o =>
{
    o.Output.DefaultFormat = "json";  // all commands default to JSON
});
```

### Feedback stays out of machine output

When the output is meant for a program, standard output carries the payload alone. Progress, status lines, notices and prompt labels go to standard error when either of these holds:

- the command renders a machine-readable format: `--json`, `--xml`, `--yaml`, or a custom transformer whose `IsMachineReadable` is `true`;
- or standard output is redirected, as in `myapp sync > report.txt` or `myapp sync | jq`.

<FeedbackStreams />

Otherwise feedback stays on standard output, beside the result. Framework diagnostics, such as a refused `--output` format, always go to standard error.

```bash
myapp sync --json > result.json   # result.json holds the JSON; progress shows in the terminal
```

<Aside type="note">
**Changed in 0.12.** Feedback used to stay on standard output in every case. To restore that, set `o.Output.FeedbackStream = ReplFeedbackStream.Output`; `ReplFeedbackStream.Error` forces standard error instead. See [which stream receives progress](https://github.com/yllibed/repl/blob/v0.12.1/docs/progress.md#which-stream-receives-progress).
</Aside>

### JSON values render as data

A handler can return a `JsonNode` or a `JsonElement`. With `--json` it is written as is; in `human` and `spectre` output, an object renders as key/value lines and an array of objects as a table, like any other result.

## Paged result rendering

When a command returns a <ApiRef uid="Repl.ReplPage`1" label="ReplPage&lt;T&gt;" /> or an <ApiRef uid="Repl.IReplPageSource`1" label="IReplPageSource&lt;T&gt;" />, the output format determines how the page is rendered:

| Format | Rendering |
|---|---|
| `human` / `spectre` (interactive TTY) | Table + integrated pager; continues fetching source pages as the user scrolls |
| `human` / `spectre` (redirected stdout) | Table for the first source page; pager suppressed; `nextCursor` hint printed |
| `json` / `xml` / `yaml` / `markdown` | Explicit page envelope: `{ "$type": "page", "items": [...], "pageInfo": { ... } }` |
| MCP structured content | `{ "$type": "page", ... }` in `StructuredContent`; text fallback via `PagedResultTextMode` |

The pager activates only for `human` and `spectre` on an interactive TTY. Redirected output and machine formats always receive the raw first page — use `--result:cursor` to advance.

See [Result-Flow Paging](/reference/result-flow-paging/) for the full source paging model, CLI options, and MCP surface.

## ANSI capability levels

Repl classifies the terminal's color capability and chooses rendering accordingly. Capability tiers (informational):

| Detected tier | Rendering |
|---|---|
| No ANSI | Plain text, no escape sequences |
| Basic | 16 ANSI colors |
| Extended | 256 colors |
| TrueColor | 24-bit color |

Two questions are answered separately: may the output be **colored**, and may it **drive the terminal** (clear the screen, move the cursor for arrow-key menus, the full-screen pager or Spectre's live displays, write shell-integration marks or advanced progress).

### Color

Checked in this order; the first row that decides wins:

| # | Check | Result |
|---|---|---|
| 1 | A hosted session states its ANSI support (for example <ApiRef uid="Repl.TerminalSessionOverrides.AnsiSupported" label="TerminalSessionOverrides.AnsiSupported" />) | that answer |
| 2 | <ApiRef uid="Repl.OutputOptions.AnsiMode" label="OutputOptions.AnsiMode" /> is `Always` or `Never` | on or off |
| 3 | The host reports no ANSI support (<ApiRef uid="Repl.CapabilityOptions.SupportsAnsi" label="CapabilityOptions.SupportsAnsi" /> is `false`) | off |
| 4 | `FORCE_COLOR` has any non-empty value, including `0` (the rule .NET 11 applies, in its console logger and in `System.Console` on Linux) | on |
| 5 | `NO_COLOR` has a non-blank value ([no-color.org](https://no-color.org)) | off |
| 6 | `CLICOLOR_FORCE=1` | on |
| 7 | `TERM=dumb` | off |
| 8 | The stream is redirected to a file or a pipe | off, otherwise on |

### Terminal control

Color must be on, and in addition one of these must hold:

- a hosted session stated its ANSI support;
- the application set `AnsiMode.Always`;
- the stream reaches a terminal, and neither `NO_COLOR` nor `TERM=dumb` (without `CLICOLOR_FORCE=1`) is set.

Independently of the color table, a hosted client that advertises ANSI through capability flags may be driven too, unless `AnsiMode.Never`, `NO_COLOR` or `TERM=dumb` says otherwise; see [Detecting Spectre capability](#detecting-spectre-capability).

So `FORCE_COLOR` or `CLICOLOR_FORCE=1` colors a file or a pipe without writing control sequences into it, and `NO_COLOR` keeps them off even where `FORCE_COLOR` turned color on. <ApiRef uid="Repl.Interaction.ITerminalInfo.IsAnsiSupported" label="ITerminalInfo.IsAnsiSupported" /> reports this answer, and <ApiRef uid="Repl.Interaction.ITerminalInfo.Palette" label="ITerminalInfo.Palette" /> the color one. Some features add their own conditions: screen clearing and progress need the stream they write to reach a terminal (a session's writer always does), and shell-integration marks are never written to redirected local output, even under `AnsiMode.Always`.

<Aside type="note">
**Changed in 0.12.1.** `FORCE_COLOR` is new, and it outranks `NO_COLOR` for color: with both set, output used to be plain and is now colored. Terminal control is now decided apart from color:

- `CLICOLOR_FORCE=1` on redirected output cleared the screen and enabled arrow-key menus there; it no longer does.
- Under `AnsiMode.Always`, a redirected local output was cleared; the clear now needs a terminal, as progress did.
- A hosted client that advertises ANSI only through capability flags got no screen clear and the line-by-line pager; it now gets the clear and the full-screen pager, as it already got shell-integration marks.
- A Spectre console colored where the terminal may not be driven is no longer interactive; see [Detecting Spectre capability](#detecting-spectre-capability).

Upgrade Repl.Spectre together with Repl.Core: Repl.Spectre 0.12.0 takes forced color from the new Repl.Core but not the rule that keeps its live displays out of a redirected output. See [ANSI Detection](https://github.com/yllibed/repl/blob/v0.12.1/docs/output-system.md#ansi-detection).
</Aside>

### Override

Override programmatically using <ApiRef uid="Repl.Rendering.AnsiMode" />:

```csharp
app.Options(o =>
{
    o.Output.AnsiMode = AnsiMode.Always;  // color on whatever the environment says; see Terminal control for its limits
    // or: Auto (default — let detection decide), Never (force off)
});
```

### JSON colorization

In interactive mode with ANSI support, `--json` output is automatically syntax-highlighted (keys in one color, strings in another, numbers in a third). No configuration required. Highlighting follows the [color rule](#color): redirected output stays plain unless color is forced.

## Render width

Repl uses the terminal width for table column sizing, word wrap, and layout decisions.

**Resolution order:**

1. `OutputOptions.PreferredWidth` (explicit override)
2. `COLUMNS` environment variable
3. Detected console window width
4. Telnet NAWS / DTTERM resize for hosted sessions
5. `OutputOptions.FallbackWidth` (default: `120`)

```csharp
app.Configure<OutputOptions>(o =>
{
    o.PreferredWidth = 160;
    o.FallbackWidth  = 80;
});
```

## Custom output transformers

Register a transformer for a new format name:

```csharp
app.Options(o =>
{
    o.Output.AddTransformer("csv", new CsvOutputTransformer());
    o.Output.AddAlias("spreadsheet", "csv");  // both --output:format=csv and --output:format=spreadsheet work
});
```

<ApiRef uid="Repl.IOutputTransformer" /> receives the handler's return value and returns a formatted string:

```csharp
public class CsvOutputTransformer : IOutputTransformer
{
    public string Name => "csv";

    public ValueTask<string> TransformAsync(object? value, CancellationToken ct)
    {
        var csv = value is IEnumerable<object> rows ? ToCsv(rows) : value?.ToString() ?? "";
        return ValueTask.FromResult(csv);
    }
}
```

## Suppressing the banner

The startup banner (shown in interactive mode) can be suppressed:

```bash
myapp --no-logo
```

Or globally:

```csharp
app.Options(o =>
{
    o.Output.BannerEnabled = false;
    // or: o.Output.BannerFormats = ["human"]  — show only in human format (default)
});
```

## Spectre.Console integration

Add `Repl.Spectre` and register:

```csharp
app.UseSpectreConsole();   // enables rich prompts and renderables in one call
```

### Returning renderables

Return any `IRenderable` from a handler — Spectre renders it automatically:

```csharp
app.Map("contacts table", (IContactStore store) =>
{
    var table = new Table()
        .BorderStyle(Style.Parse("grey"))
        .AddColumn("[bold]Id[/]")
        .AddColumn("[bold]Name[/]")
        .AddColumn("[bold]Email[/]");

    foreach (var c in store.All())
        table.AddRow(c.Id.ToString(), c.Name, c.Email);

    return table;
});
```

### Color palette and style

Use Spectre.Console's full `Markup` and `Style` API anywhere an `IRenderable` is expected:

```csharp
return new Markup("[green bold]Success![/] Contact added.");
```

```csharp
return new Panel(new Markup(content))
    .BorderStyle(Style.Parse("blue"))
    .Header("[bold]Summary[/]");
```

### Available renderables

| Type | Description |
|---|---|
| `Table` | Grid with borders, alignment, and markup |
| `Panel` | Box with optional header and border |
| `Tree` | Hierarchical tree view |
| `BarChart` | Horizontal bar chart |
| `BreakdownChart` | Proportion chart |
| `Calendar` | Monthly calendar with highlighted dates |
| `JsonText` | Syntax-highlighted JSON |
| `FigletText` | Large ASCII art text |
| `TextPath` | Breadcrumb path rendering |
| `Markup` | Inline styled text |
| `Grid` / `Columns` | Free-form layout |
| `Rule` | Horizontal divider |
| `Progress` / `Status` | Live progress widgets |

### Detecting Spectre capability

Spectre rendering follows the same [ANSI detection](#ansi-capability-levels) as the rest of the framework — no configuration required:

- **Colors** follow the [color rule](#color); when it says no, the color system degrades to `NoColors` and output stays plain text. A hosted client that advertises ANSI only through capability flags (terminal identity, control messages) gets Spectre styling even when the server console's own state says no; `AnsiMode.Never`, `NO_COLOR` and `TERM=dumb` still win over that fallback.
- **Live displays and prompts**: Spectre animates `Progress` and `Status` only when its console is interactive and ANSI. A console that is colored but may not [drive the terminal](#terminal-control) (color forced onto redirected output, or onto a terminal under `NO_COLOR` or `TERM=dumb`) is not interactive: live displays print static lines, a prompt on an injected `IAnsiConsole` fails as it does in any non-interactive console, and Repl's own text prompts answer <ApiRef uid="Repl.Interaction.IReplInteractionChannel" /> requests instead of Spectre's. An uncolored console stays interactive: prompts on an injected `IAnsiConsole` keep working under `app | tee log`, and `NO_COLOR` on a terminal keeps Spectre's prompts.
- **Unicode box-drawing** degrades per output sink: full Unicode borders when the sink's encoding carries them, Spectre's square ASCII-safe fallback on a legacy OEM codepage, and ASCII transliteration (`+`, `-`, `|`) when no box glyph survives (redirected consoles, CI logs, pipes). The active verdict is exposed as `SpectreTerminalDetection.CurrentBoxDrawingSupport` for diagnostics.
- **CI logs are plain by default** — Spectre's built-in CI enrichers are disabled so they cannot override the host detection. Set `FORCE_COLOR=1` (or `CLICOLOR_FORCE=1`) in the workflow to restore colored logs.

Outside a Repl container (bare `AddSpectreConsole()` without `UseSpectreConsole()`), the profile falls back to Spectre's own detection.

## Help output formatting

Help can also be rendered in structured formats:

```bash
myapp contacts --help            # human-readable
myapp contacts --help --json     # machine-readable JSON
```

The JSON format returns a structured <ApiRef uid="Repl.Documentation.ReplDocumentationModel" /> — useful for tooling, documentation generators, and agents.

<Aside type="tip">
Machine-readable help is the foundation for agent discovery. See [Agent-Native Development](/reference/agent-native/) for how agents use this to explore your app autonomously.
</Aside>

## `IAnsiConsole` injection

`Repl.Spectre` registers Spectre's `IAnsiConsole` in DI, bound to the current session's output stream. Inject it directly when you need full Spectre control:

```csharp
app.Map("demo", (IAnsiConsole console) =>
{
    console.Write(new FigletText("Repl").Color(Color.Blue));
    console.MarkupLine("[bold green]Ready.[/]");
});
```

This is session-safe in hosted mode — each session gets its own `IAnsiConsole` bound to its output stream.

A prompt on the injected console fails where the console is colored but may not drive the terminal (see [Detecting Spectre capability](#detecting-spectre-capability)); ask through `IReplInteractionChannel` to keep working there.
