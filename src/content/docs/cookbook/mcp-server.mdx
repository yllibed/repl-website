`Repl.Mcp` lets your app expose its command graph as an MCP server. It is not a standalone MCP server by itself: the app you build with Repl is the server that agent hosts launch. Every `Map(...)` becomes a tool; return values, resources, and prompts are all first-class.

<Aside type="tip">
  Full runnable code: [`samples/08-mcp-server`](https://github.com/yllibed/repl/tree/v0.12.1/samples/08-mcp-server)
</Aside>

## Enable the MCP server

```csharp
using Repl.Mcp;

app.UseMcpServer();
```

Start with:

```bash
myapp mcp serve
```

Configure your agent host to launch your app:

```json
{
  "mcpServers": {
    "myapp": {
      "command": "myapp",
      "args": ["mcp", "serve"]
    }
  }
}
```

## Tools

Every `Map(...)` becomes an MCP tool automatically. The tool name is the route, description comes from `[Description]` or `.WithDescription(...)`.

```csharp
app.Map("contacts list", static (IContactStore store) => store.All())
    .WithDescription("List all contacts");

app.Map("contacts add {name} {email:email}", static (string name, string email, IContactStore store) =>
{
    store.Add(name, email);
    return Results.Success($"Added {name}.");
})
.WithDescription("Add a new contact");
```

## Resources

Expose read-only data as MCP resources:

```csharp
app.Map("contacts export", static (IContactStore store) => store.All())
    .AsResource()
    .WithDescription("All contacts as a JSON resource");
```

## Prompts

Register reusable prompt templates:

```csharp
app.Map("prompts summarize {contact_id:int}", static (int contactId, IContactStore store) =>
{
    var contact = store.Get(contactId);
    return new McpPromptResult
    {
        Messages = [new McpMessage(McpRole.User, $"Summarize the following contact: {contact}")]
    };
})
.AsPrompt()
.WithDescription("Generate a summary prompt for a contact");
```

## MCP Apps

Return HTML from a command and register it as an MCP App resource — the client renders it as an interactive panel:

```csharp
using System.Net;   // WebUtility.HtmlEncode

app.Map("contacts dashboard", static (IContactStore store) =>
{
    var contacts = store.All().ToList();
    return $$"""
        <html>
          <body>
            <h1>Contacts ({{contacts.Count}})</h1>
            <ul>{{string.Join("", contacts.Select(c =>
                $"<li>{WebUtility.HtmlEncode(c.Name)}</li>"))}}</ul>
          </body>
        </html>
        """;
})
.AsMcpAppResource()
.WithDescription("Open the contacts dashboard");
```

Always HTML-encode user-controlled values. Raw interpolation of contact data into HTML creates stored XSS — an attacker who controls the data can execute scripts in the MCP client's WebView.

## Behavioral annotations

Tell the agent how it should handle your tools:

```csharp
app.Map("contacts delete {id:int}", static (int id, IContactStore store) =>
{
    store.Delete(id);
    return Results.Success("Contact deleted.");
})
.Destructive()
.WithDescription("Delete a contact permanently");
```

| Annotation | Meaning |
|---|---|
| `.Destructive()` | Agent should warn before calling |
| `.ReadOnly()` | No side effects — call freely, parallelize |
| `.Idempotent()` | Safe to retry on transient failure |
| `.OpenWorld()` | Reaches external systems (email, HTTP, etc.) |
| `.LongRunning()` | Slow-operation hint in help and docs; not advertised to MCP clients as task support |

## Automation visibility

Some commands are useful for humans in REPL but should be hidden from agents:

```csharp
app.Map("debug reset", static (IContactStore store) => store.Clear())
    .AutomationHidden();
```

`.AutomationHidden()` hides the command from MCP and other programmatic surfaces while keeping it accessible in the interactive REPL and `--help`.

## Restrict file paths

A tool that opens a file the agent names must keep it inside the directories the server may read. Take those directories from the server's own configuration, and resolve the path against each one:

```csharp
// Fully qualified directories this server may read, from its own configuration.
IReadOnlyList<string> workspaceRoots = ["/srv/projects"];

app.Map("analyze {path}", async (string path) =>
{
    foreach (var root in workspaceRoots)
    {
        var full = Path.GetFullPath(path, root);
        var relative = Path.GetRelativePath(root, full);
        if (relative != ".." && !relative.StartsWith(".." + Path.DirectorySeparatorChar, StringComparison.Ordinal)
            && !Path.IsPathRooted(relative))
        {
            return await AnalyzeFile(full);
        }
    }

    return Results.Error("outside_root", $"Path '{path}' is outside the configured directories.");
});
```

<Aside type="caution">
This check works on the path text: it does not resolve symbolic links or junctions. If the directories can hold content you do not control, such as cloned repositories or uploads, also reject a path in which any segment is a link (`FileSystemInfo.LinkTarget` is not null), or run the server under an account that can read only those directories.
</Aside>

MCP client roots, which a host declares for the same purpose, are deprecated by `2026-07-28`; see [client roots](/reference/mcp-advanced/#client-roots-and-soft-roots) for hosts that still use them.

## Agent-host setup

For local samples, prefer absolute project paths in host configs. Build the
sample once before launching it from an MCP host:

```bash
dotnet build samples/08-mcp-server/McpServerSample.csproj
```

Then configure the host to run without rebuilding. Cursor, Cline, Claude-style
clients, and many generic MCP clients use the `mcpServers` shape:

```json
{
  "mcpServers": {
    "repl-contacts-sample": {
      "command": "dotnet",
      "args": [
        "run",
        "--no-build",
        "--project",
        "/absolute/path/to/repl/samples/08-mcp-server/McpServerSample.csproj",
        "--",
        "mcp",
        "serve"
      ]
    }
  }
}
```

VS Code/Copilot uses top-level `servers` in `.vscode/mcp.json`:

```json
{
  "servers": {
    "repl-contacts-sample": {
      "type": "stdio",
      "command": "dotnet",
      "args": [
        "run",
        "--no-build",
        "--project",
        "/absolute/path/to/repl/samples/08-mcp-server/McpServerSample.csproj",
        "--",
        "mcp",
        "serve"
      ]
    }
  }
}
```

Rebuild-on-launch `dotnet run` host configs are fragile because cold builds can
exceed startup timeouts or emit build output before the MCP JSON-RPC stream
starts. Use `.cursor/mcp.json` for Cursor, Claude Code's MCP
registration/settings flow, Cline's MCP settings, or the VS Code-specific shape
above. Review commands before enabling them: local MCP servers run code on the
user's machine.

If .NET was installed per user with dotnetup and the host does not start from
the user's shell, `dotnet` may not be found; see
[dotnetup installs and agent hosts](/reference/dotnet-11/#dotnetup-installs-and-agent-hosts).
